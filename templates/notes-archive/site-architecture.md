# 为什么要拆分

如果一个个人站点同时承担品牌展示、服务转化、知识沉淀和日常记录，那么它天然就不是单一内容系统可以优雅覆盖的。

我更倾向于把它拆成四层：

- 主站负责品牌、服务、入口和信任感
- 笔记负责快速记录和轻量输出
- 知识库负责结构化内容和长期维护
- 评论与留言负责互动和通知

## 笔记为什么适合 Markdown

笔记最重要的是轻。

1. 打开编辑器就能写
2. 不依赖在线平台的结构限制
3. 可以直接跟代码仓库一起管理
4. 上线方式稳定，迁移成本低

这类内容往往是片段、结论、草图和清单，本地 Markdown 已经足够。

## 知识库为什么保留飞书

知识库需要目录、层次、可维护性和团队化的阅读体验。

> 这类内容不是“顺手记一条”，而是“希望以后还能回来查”的资料。

所以它更适合放在飞书，再由站点做只读展示。

## 一个原则

不要让内容系统反过来定义网站结构。  
网站应该先明确自己的业务边界，再决定每一类内容放在哪里。
